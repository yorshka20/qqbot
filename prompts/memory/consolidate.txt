## 每条事实的写法
- 一条只说一件事，简洁的陈述句，不超过 50 字。
- 用户记忆的主语默认是该用户，不必重复写"用户"；提到别人时写明是谁。
- durability：
  - `stable`：身份、长期偏好、长期习惯、持续有效的要求、群规、群的长期背景。
  - `transient`：近况、计划、正在做的事、最近在聊的话题、一次性的事件。

## 处理每条候选
- 与人工记忆重复或矛盾 → 不输出任何操作，等于丢弃。这条优先于下面所有规则。
- 和某条已存记忆说的是同一件事、没有新细节 → `confirm` 那条。
- 给某条已存记忆补充了细节，或者和它矛盾（情况变了）→ `update`：写出更正或合并后的新内容，替换被涉及的条目。
- 候选涉及的几条已存记忆彼此重复 → `update`，把它们合并成一条。
- 某条已存记忆被候选明确推翻，又没有可写的新内容 → `delete`，写明原因。
- 全新的信息 → `add`。
- 价值低、一次性的请求、或不属于这类记忆的 scope → 不输出任何操作，等于丢弃。

## 处理与人工记忆冲突的已存记忆
不管候选有没有涉及，已存的自动记忆都要和人工记忆对一遍：
- 与人工记忆矛盾，按人工记忆改正后仍有人工记忆没写到的内容 → `update`，写出改正后的内容。
- 与人工记忆矛盾，改正后剩下的内容人工记忆都已写到；或者本身就被人工记忆完整覆盖 → `delete`，原因写"与人工记忆矛盾"或"与人工记忆重复"。
- 只是比人工记忆多了细节、并不矛盾 → 保留，不输出操作。

除此之外，候选没涉及的已存记忆不要输出任何操作。不要为了措辞更好而 update。

## 输出
只输出 JSON：
{
  "operations": [
    { "op": "add", "scope": "preference:game", "durability": "stable", "content": "……" },
    { "op": "confirm", "id": 3 },
    { "op": "update", "ids": [2, 5], "scope": "identity:work", "durability": "stable", "content": "……" },
    { "op": "delete", "id": 4, "reason": "……" }
  ]
}
没有要做的操作时输出 {"operations": []}。
